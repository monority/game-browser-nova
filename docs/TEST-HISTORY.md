Re-run after the patch: every behavioural mutation now fails its file, **32 mutations total** (22 caught at once, 8 holes closed, 2 equivalent), suite still 107 green. Budget rule: a spec exists only for what a headless unit test cannot observe (DOM wiring, panel text, persistence, renderer lifecycle); a new E2E assertion joins an existing journey instead of adding a spec.

## 3. What the two campaigns established

- **A deleted test cannot fail.** Cutting the suite raises the question the
  suite itself cannot answer, so every trim is now followed by a mutation
  campaign: inject one deliberate regression, run the file that should catch
  it, expect red.
- **Green is not the same as observed.** The first campaign found eight laws
  with no observer at all — an embargo rounding down, a workshop batch
  creating a plank ex nihilo, camps ignoring their network position, a
  harvest windfall nobody pinned, a future save version loading as the
  current one.
- **Two survivors were equivalent, not holes.** `consumeFood`'s floor and
  ceil on an integer fed count, and `regrowAdjacent`'s ceiling when
  `amount` is 1 on integer stock: neither can change an observable.
  Declaring an equivalent mutant is a claim to state in the table, never a
  way to silence the probe.
- **Latent vacuity is separate from survivor count.** Two assertions that
  only walked a collection (`every()` over an empty list, a `false` per
  residence) were pinned with a length first — measured, not assumed: the
  empty-`AGE_MILESTONES` mutation went red even without the guard, so the
  guard closed a latent vacuity, not a reported hole.
